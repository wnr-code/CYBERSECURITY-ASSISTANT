# Android app foundation

This directory contains the first Flutter app foundation for Cybersecurity Assistant:

- AndroidX SplashScreen is explicitly installed in the launcher before `FlutterActivity`, delegating to the Android 12+ native API and providing a branded Android 6–11 compatibility splash. The Flutter handoff then fades to the dashboard; SQLite history loads asynchronously and never gates dashboard startup.
- Four primary destinations (Home, Assessment, Reports, Settings) in a rounded floating bottom bar on compact layouts, plus a centered secondary AI shortcut. Settings contains preferences, privacy, diagnostics, and the endpoint reachability check; Reports and Assessment are not duplicated there. Wide layouts use a NavigationRail. Assistant supports opt-in Gemini chat and reviewed registered-tool proposals; it is not the full AI Expert Engine. Local AI inference is not implemented.
- A focused Assessment accepts one authorized domain/URL per run and shows only built-in DNS, TLS, and HTTP checks whose on-device runtime readiness is `ready`. Checks run sequentially through the registry-only orchestrator, continue after individual failures, and display each actual outcome. Multi-target batch scanning is not implemented.
- The searchable Catalog contains only built-in checks that passed the same readiness probe and hands off to Assessment. Gemini/Cloudflare setup and package entries are not duplicated there.
- Market is the canonical provider/package center, opened from the persistent app-bar store icon or the Assistant setup CTA. Providers lists only Gemini and Cloudflare with Available, Configured, Connected (or token verified for Cloudflare), Unavailable, and Error statuses. Packages lists only installable/installed verified data packages; unsupported runtime/plugin previews are hidden. The AI Models tab is hidden until on-device inference is implemented.
- Settings → Endpoint reachability test keeps the working unauthenticated HTTPS GET check. Generic provider guides and duplicate credential entry forms are removed.
- A separate, persistent Market with provider setup/status and an installable-data package manager; package compatibility checks include runtime/ABI constraints. An offline JSON Knowledge Pack fixture is SHA-256 verified and stored as data under app-private storage. Current Market installs data only; provider code/runtime modules cannot yet be installed or removed individually. The future modular-delivery target remains documented at [Market Modular Delivery](../../docs/market-modular-delivery.md); Local AI is not exposed in the current UI.
- The selected robot-and-shield artwork in `assets/branding/app_icon_source.png` is rendered into Android legacy density launcher icons and an Android 8+ adaptive icon by `tool/configure_android.py`; Android 12+ splash branding remains a separate vector mark.
- Allowlisted GitHub latest-release metadata viewer with constrained URL validation and publisher digest display; it does not download or execute assets.
- Executable P0 DNS, TLS certificate, and HTTP header/API response adapters; HTTP checks use one bounded GET (32 KiB maximum response body) to the exact query-free authorized HTTPS path and do not follow redirects. Raw response bodies are analyzed in memory and never returned or persisted; findings/evidence contain only redacted field paths and bounded metadata.
- Registry-ID-only multi-check orchestration (no free-form shell), explicit target confirmation, HTTPS/path/port validation, per-check completed/failed outcomes, and a result marker recording that the self-attestation gate was accepted. The marker is not proof of authorization.
- The draggable Terminal is an app-local, restricted command workspace, not Termux and not an Android/Linux shell. It cannot run arbitrary `bash`, package installers, or system commands; only registered safe commands are accepted. Edge Panel exposes only working actions (Assessment, Terminal, plus provider views only after a successful connection test); primary destinations and Catalog are accessed from their normal navigation points.
- Local deterministic response analysis for JSON validity, sensitive-looking JSON field names, and common stack-trace/database-error signatures; findings are heuristic, not an AI analysis or proof of vulnerability.
- Session history, user-confirmed JSON report copy, session clearing, and opt-in on-device SQLite result storage with a bounded history.
- Assistant with a floating, rounded chat composer and opt-in Gemini chat using a user-owned API key, locally saved provider-scoped conversation-sharing consent (revocable in Privacy Settings), and separately guarded registered-tool proposals; it is not the complete AI Expert Engine.
- Market Provider Manager for Cloudflare and Gemini, plus a fail-closed Local AI path based on official `ggml-org/llama.cpp` source commit `ea722948146befb23c9529c1ec7f59fb2f34911f`. An opt-in Android NDK/CMake build configuration, CPU-only native JNI bridge, Flutter MethodChannel adapter, and source-built APK audit are implemented. The pinned codeload source archive SHA-256 is `05b362e97564f2e449440f13878c43991a13b6029214dbcb0d1b116b20365ec2`; it stays in ignored build cache, not Git. A single Qwen2.5 Q4_K_M GGUF candidate is now pinned to a user-supplied immutable revision, license, size, and SHA-256. The app streams a user-selected file into private storage and refuses native load unless exact size and SHA-256 match. The physical phone must perform this actual file verification and native inference test; model bytes/checksum do not imply the model is risk-free, and Local AI remains Not Ready until required phone tests pass.
- Widget and unit tests covering navigation, policy validation, provider/tool registries, orchestration guards, GitHub metadata parsing, report JSON, SQLite round-trips, secure-store namespacing/validation, provider credential entry/status/delete flow with a fake backend, response-header secret redaction, history limits, and finding ordering; Python unit tests cover the generated-Android hardening configurator and analyzer diagnostic parser.

## Navigation and current boundaries

- **Home** is a local summary, not a live network map or composite risk score.
- **Assessment** runs only readiness-confirmed checks against one authorized URL/domain per run; run another target separately.
- **Security tool catalog** shows only checks whose runtime readiness probe passed on this device. It does not list providers or Market packages.
- **Market → Providers** is the single setup location for Gemini and Cloudflare. Paste only the raw key/token (not a URL or `Bearer` prefix), tap **Save securely**, then **Test Connection**. Saving stores the secret locally and makes no network request. Status distinguishes **Available**, **Configured** (saved but untested), **Connected** (successful connection test), **Unavailable**, and **Error**. Cloudflare's **Token verified** status confirms only the token verification endpoint; account and zone read permissions are tested separately. Cloudflare Account ID is optional and never substitutes for the API token.
- **Market → Packages** shows installable/installed data packages only; they are stored as data, not executed as programs. The AI Models tab is hidden until model inference works.
- The **app-bar store icon** opens Market; the Assistant setup CTA routes there when needed. Settings → **Endpoint reachability test** sends one unauthenticated HTTPS GET after authorization; it is not a provider authentication check.
- **App Terminal** accepts registered safe commands only. It is not Termux, `bash`, or a system shell. Edge Panel contains only Assessment, Terminal, and provider views after their connection tests succeed; Reports, Settings, and Catalog stay at their normal single navigation points.

Android secure-storage behavior still requires real-device verification. If saving shows an error, capture the error code/message with the API key hidden; never send the key itself.

APK integrity is wired into the generated Android launcher. A release build must supply `TRUSTED_APK_CERT_SHA256` (one or more comma-separated SHA-256 fingerprints for the certificate that signs the APK delivered to users) when running `tool/configure_android.py`; for Play distribution, pin the **Play App Signing certificate**, not the upload key. The debug certificate is never a trusted release identity. Release startup fails closed if the pin is absent or the Package Manager signer differs. The native verifier reports package/version/signer, installer source, and a SHA-256 digest over the installed base and split APK files. Dart anchors that identity/digest in Android Keystore-backed secure storage, rejects same-version content changes and downgrade, and permits a higher version only when the signer is unchanged and installer source is Google Play. APK installation/update itself is deliberately delegated to Android Package Manager/Google Play; this app has no sideload or hidden updater. These controls have not yet been compiled or device-tested in this checkout, so they must not be described as active protection until a real signed APK is validated.

Market exposes Cloudflare, Gemini, and a Local AI entry that remains Not Ready until the native runtime and a verified compatible model are proven. Cloudflare verifies token status and supports read-only account/zone listing and zone details; each read's permission is checked independently, and no DNS-record, Workers, or write API is exposed. Gemini reuses the existing adapter and current fixed model, with provider-scoped conversation-sharing consent saved locally after the user checks the consent box once. Consent is revoked through Privacy Settings; tool proposals remain separately reviewed. Local AI's Diagnostic Test remains available while Not Ready and reports blocked stages without enabling normal inference. See [the provider Market implementation notes](../../docs/market-priority-providers.md) for scope, permissions, status semantics, official guidance, and test limitations.

The built-in checks are deliberately limited: DNS uses Android's system hostname resolver and can classify returned A/AAAA addresses, but does not expose CNAME, MX, TXT, NS, or SOA records; TLS performs one standard-port handshake and reports the peer certificate subject, issuer, validity dates, remaining days, and platform handshake validation for the requested hostname; HTTP performs one GET to the exact HTTPS path, reads at most 32 KiB of body, and never follows redirects. TLS/HTTP connections pre-resolve the host, reject private, link-local, reserved, and metadata destinations by default, then connect only to the approved resolved address set to avoid a second DNS lookup/rebinding window. The optional local/private-target checkbox is off by default and should only be enabled for explicitly authorized lab systems; known cloud metadata hostnames and addresses remain blocked even when it is enabled. Header and response indicators are deterministic heuristics and context-dependent (for example, an API may not need browser-oriented headers). Findings carry separate confidence and severity labels; current rules produce potential or informational indicators, not confirmed vulnerabilities. The response body is not retained; common sensitive JSON property names are reported only as redacted paths. Common secret-bearing response-header names are redacted, and common bearer/basic credentials, JWT-like strings, sensitive query parameters, and URL userinfo are sanitized from header values. Provider-specific encodings may not be recognized. Review exported reports before sharing. The checks do not exploit vulnerabilities, crawl pages, or run arbitrary commands. They are not a substitute for a full security assessment. Only assess targets you own or are explicitly authorized to test. The checkbox is a user-consent gate, not independent proof of authorization. See [the device test procedure](../../docs/android-device-testing.md#7-owner-run-https-api-path-procedure) for a self-run API path test.

The Connection Manager test requires an in-app self-attestation that the user owns or is authorized to test the entered endpoint; editing the endpoint clears that confirmation. It then sends one unauthenticated HTTPS GET, does not follow redirects, sends no credentials, and discards the response body. Any HTTP response counts as reachable; it does not authenticate against a provider or establish that an integration is correctly configured. The checkbox is not independent proof of authorization. Do not use URLs containing secrets.

Cloudflare and Gemini provider flows use user-owned credentials through the secure credential boundary; Cloudflare performs only the documented read-only account/zone operations, while Gemini sends conversation data only after the user grants locally saved, provider-scoped consent. Consent can be revoked in Privacy Settings, and tool proposals continue to require separate review. This storage path and its Android Keystore behavior/native configuration have not been runtime-tested. Do not enter production secrets until those checks pass. Other provider catalog entries remain guide-only and do not use saved credentials. Results remain in memory unless the user explicitly saves an individual completed check to SQLite; saved results are stored in the app-private database, are not encrypted, and are not synced. Unsaved session results are discarded when the app process ends. Optional provider modules, Local AI inference, and modular install/uninstall delivery are future work.

## Run when Flutter is installed

This app currently requires Flutter >=3.47.0 and Dart >=3.13 because it uses the standalone `material_ui` package. The repository contains Dart/Flutter source and package metadata but no committed/generated Android Gradle wrapper or platform project. This coding environment does not have a local Flutter/Android toolchain; GitHub Actions generates the Android scaffold temporarily and runs hardening, dependency resolution, analyzer, tests, APK build, and artifact upload. From this directory on a machine with Flutter and Android SDK installed, generate the platform scaffold, apply the hardening script, then run:

```sh
flutter create --platforms=android --project-name cybersecurity_assistant --org org.cybersecurityassistant .
python3 -m unittest discover -s tool -p 'test_*.py' -v
python3 tool/configure_android.py
# For a trusted Play release, obtain the SHA-256 of the public **Play App Signing** certificate from Play Console (or inspect a Play-delivered APK with `apksigner verify --print-certs`), remove the colons from the fingerprint, then rerun configuration with the 64 hexadecimal characters. Do not use the upload-key fingerprint:
TRUSTED_APK_CERT_SHA256="<64-hex-certificate-fingerprint>" python3 tool/configure_android.py
flutter pub get
flutter analyze
flutter test
flutter build apk --debug
# Standard Flutter AAB output without release signing.
flutter build appbundle --debug
# Separate APKs per supported Android ABI in debug mode.
flutter build apk --debug --split-per-abi
# For Play release: configure signing via local/CI secrets, then use --release.
flutter run
```

For the opt-in llama.cpp source build, install Android NDK and CMake first, then run `LOCAL_AI_NATIVE_BUILD=1 python3 tool/run_flutter_build.py`. This fetches only the pinned official codeload archive, verifies its SHA-256 before extraction, configures Android `arm64-v8a` with all accelerator backends disabled, and audits the resulting APK's JNI ELF/dependencies. The Qwen GGUF pin is not bundled in the APK. On the phone, use **Download, verify, and load on this phone** in Market → Providers → Local AI. Before downloading model bytes, the app queries the pinned Hugging Face revision with full metadata, then requires the expected publisher, repository, immutable revision, Apache-2.0 license, exact filename, size, and publisher SHA-256. It downloads in HTTP byte ranges to a resumable temporary app-private file, independently checks the complete byte count and SHA-256, and asks the native bridge to re-check both values before llama.cpp opens it. Any metadata or byte mismatch fails closed; interrupted ranges retry from the exact saved offset. After first verification, a private receipt matching the build's immutable pin lets the native bridge rehash and reload the installed model after app restarts, including offline. Market offers an explicit remove action for the pinned model and partial download. Local inference has a 60-second native deadline and a Dart timeout/cancel path; it does not fall back to cloud. Local AI stays Not Ready until the separate physical offline test is also completed.

## Local AI physical-phone validation (no emulator)

The workflow does not boot Android emulators. On a workflow-dispatch run, the source-native ARM64 APK is uploaded as `local-ai-arm64-native-apk-<run>-<attempt>` **only if** its source, ABI, ELF dependency, DEX, and JNI audit passes. The regular `cybersecurity-assistant-debug-apk-*` artifact is not a native-audited substitute. Download the source-native artifact from GitHub Actions on your Android phone only after the audit succeeds; if there is no such artifact, CI has not produced a validated native APK yet.

On a compatible physical ARM64 phone:

1. Install the audited native APK using Android's package installer and launch it. Do not enable installation from unknown sources except as Android requires for your chosen browser/file manager; turn that permission back off afterward.
2. Open **Market → Providers → Local AI → Download, verify, and load on this phone**. The app requests Hugging Face metadata for the immutable revision and checks publisher, repository, revision, license, exact file record, size, and SHA-256 before it starts the model download. Keep at least the model size plus the app's safety margin free in internal storage.
3. The app streams the file from the pinned official Hugging Face resolve URL to temporary app-private storage, then checks the exact 1,117,320,736-byte size and complete SHA-256 `6a1a2eb6d15622bf3c96857206351ba97e1af16c30d7a74ee38970e434e9407e`. Any mismatch removes the temporary file and prevents loading. The native bridge independently checks the pin before llama.cpp opens the model. A matching hash checks file identity against the configured pin; it does not prove the model is free from every risk.
4. If verification and native model load both succeed, open Chat, choose Local AI, and send a simple test prompt. Record the response, latency, and any error. The model may exceed this phone's available memory; a native load/inference failure must remain visible and must not trigger cloud fallback.
5. Use **Copy report** only if you choose to share diagnostic output; review it first. For offline testing, enable airplane mode, ensure Wi-Fi and mobile data are off, repeat a local Chat prompt, and paste the result/report here if you want help. No report is sent automatically.
6. Keep Local AI **NOT READY** until physical-device ABI/native load, available resources, approved model SHA-256 integrity, model load, real inference, and airplane-mode inference all pass. The Diagnostic Test is available in both readiness states and never changes readiness; normal AI inference remains independently gated.

CI evidence covers builds/static audits only; it cannot establish physical-device compatibility, real inference, or offline operation.
